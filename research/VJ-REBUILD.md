# MIXDESK 本地 VJ 重实现

## VJ 全屏与界面修整（2026-10-20）

视频画面从通道卡片中拆分出来，固定比例只作用于画面；下方控制条在桌面、平板和手机宽度均保持可见。每路加入浏览器全屏切换。另有独立双路弹出输出窗，可拖至第二屏；主窗视频控制将位置、播放、速度、透明度和可见性同步给静音输出层，弹窗打开或载入视频时会恢复当前定位。REA 的 `Video::run` 读取两路 OpenCV 帧并检查窗口全屏状态，可佐证有全屏状态上报，但不能证明网页全屏与原版输出等价。

验证：`tests/vj.spec.js` 检查 1440 / 800 / 390 px 下控件边界、全屏进退，以及生成的 WebM 在主窗和弹窗之间的真实解码、透明度和播放状态同步；VJ 专项与完整 139 项回归均已通过。输出窗测试实际检查弹窗中的视频解码、静音、播放推进、透明度和停止状态。需在操作系统中手动移动输出窗到目标显示器；浏览器没有可靠 API 指定某一物理显示器，也未实现协议级窗口尺寸/位置控制或 OpenCV 帧处理。

## 本地歌词层（2026-10-21）

REA 静态符号显示原版存在 `Lyrics::setRate(float)`，并且 VJ 设置页有 `SettingsVjing::addLyrics`。这只能证明原版有歌词相关入口和速度接口，不能推出原版歌词文件格式、在线服务或渲染细节。因此 MIXDESK 增加了一个明确有界的本地歌词子集：导入 LRC、SRT 或 `时间 | 文本` / Tab 时间轴文本，按对应视频位置实时选择当前句，跟随 Deck 定位和速度，支持显示、透明度、字号、顶部/中部/底部位置和阴影开关；主 VJ 层与独立输出窗共享同一份歌词状态。歌词文件、已解析时间轴和样式保存到 IndexedDB，刷新后恢复。

`parseLyrics` 会拒绝没有时间轴的文本，SRT 时间段优先于相邻句推断结束时间，LRC 的重复时间标签展开为独立 cue。歌词层不会进入音频路径，也没有声称实现 DJUCED 原版字幕、歌词在线下载、动画歌词或授权策略。

验证：`tests/vj.spec.js` 的歌词测试覆盖 LRC/SRT/管道文本解析、定位后当前句、字号和 DOM 渲染、IndexedDB 恢复。当前已增加每通道浏览器滤镜特效（柔焦、亮度、对比度、饱和度、灰度、棕褐、反色、色相）与 CSS 动画（呼吸、漂移、缩放、旋转、闪烁），并在主窗和独立输出窗验证特效、动画、透明度及播放状态同步。它们是可观察行为的同类实现，仍未恢复原版 `SettingsVjing::addEfects` / `addAnimations` 对应的专有 DSP、素材服务、参数编辑器、动画预设或 PRO 权限策略。

## REA 视频命令解析补充（2026-10-20）

`evidence/rea/video-read.json` 对 `Video::read`（`0x10074c000`）的伪代码确认，视频控制命令通过逐行、Tab 分隔的文本输入解析。可直接辨认的操作包含 `hide`、`size`、`move`、`path`、`rate`、`play`、`pause`、`stop`、`pos`、`load` 和 `alpha`；`play` / `stop` 带通道索引，`pause` / `pos` 带毫秒位置字段，`path` 将文件路径分配给指定通道，`rate` 按通道写入速度值，`alpha` 写入透明度及其互补值。`size` / `move` 写入视频窗口几何数据。这是静态伪代码可见的解析与字段行为，不能据此推断外部窗口和特效输出已经完整复现。

MIXDESK 双通道网页现已各有播放/暂停、停止、时间定位、速度、透明度、显示，以及跟随对应 A/B 音频台或独立运输开关。跟随模式的播放按钮操作同编号 Deck，独立模式由静音 HTMLVideoElement 自行运输；同步只作用于跟随模式。通道设置和时间位置写入 IndexedDB 会话，视频没有第二路音频输出。

本轮验证扩展为 `tests/vj.spec.js` 的独立运输按钮、显示/透明度/速度/定位、真实浏览器 WebM 解码与 IndexedDB 刷新恢复。该测试不验证原版 OpenCV 处理、窗口几何 `size/move`、外接显示器输出、VJ 预设、动画歌词、网络素材、PRO 权限、不同浏览器编解码兼容或原版同步抖动与帧精度。

MIXDESK 的 VJ 模块按 DJUCED 6.6.1 二进制中观察到的 `Video` 双通道接口建立了独立实现。REA 证据显示原版提供两个通道，并分别暴露 `setVideo(QString, bool, int)`、`setRate(double, int)`、`play(int)`、`pause(long, int)`、`stop(int)`、`setPosition(long, int, …)`、`setOpacity(double, int)`、`hideVideo()`、`resizeVideo()` 和 `moveVideo()`。

当前实现：

- 每个 A/B Deck 对应一个本地视频层；
- 支持浏览器能解码的 MP4、WebM、MOV、M4V 和 OGV 文件；
- 视频层独立播放、暂停、停止、定位、速度、透明度和显示状态；
- 音频路径固定静音，视频音轨不会重复进入 DJ 主输出；
- Deck 播放/暂停、定位和速度变化会同步到对应视频层；
- 使用 Blob URL，导入资源仅在本地浏览器会话中处理；
- 将本地文件和通道状态保存在 IndexedDB，启动后恢复文件、定位点、透明度、速度和显示状态；恢复时仍保持暂停，Deck 运输状态随后按 A/B 映射同步；
- 不复制 DJUCED 原版视频素材，也不声称恢复原始 C++ 源码。

尚未等价实现的原版能力包括 OpenCV 帧处理、协议级外部窗口几何、原版专有视频 DSP、网络素材服务、VJ 预设和 PRO 许可证策略。当前浏览器特效、动画和歌词是已测试的同类实现，不代表原版参数曲线、素材库或授权范围。浏览器能否解码具体容器和编码仍取决于系统浏览器。

验证由 `tests/vj.spec.js` 覆盖：双通道状态、静音约束、独立透明度/显示控制、Deck 播放状态/定位/速度同步，以及浏览器现场生成 WebM 的真实解码、定位、IndexedDB 刷新恢复。WebM 测试文件由 Canvas 与 MediaRecorder 生成，不包含 DJUCED 素材。
