# MIXDESK 0.8.4 音频核心优化

日期：2026-10-22。本轮优化独立网页音频引擎，目标是消除已复现的静音间隙、硬切突变和 Slip 抓碟时间线错误。未恢复 DJUCED 源码或其原生 DSP 算法。

## 已完成

| 路径 | 复现的问题 | 0.8.4 行为 |
| --- | --- | --- |
| 播放、跳点、暂停、切换方向 | 音源直接连接或断开，波形可发生硬切 | 每个播放实例在 DSP 后有独立 4ms 线性淡入 / 淡出；快速连续命令也保留正确的包络起点 |
| 连续移调 | 修改半音会销毁并重建处理器；合成测试测得约 145ms 静音 | 已运行的 SoundTouch 处理器直接更新 AudioParam；双声道测试检查连续音频和 ±12 半音频率 |
| Slip 抓碟 | 松手从抓碟位置续播，丢失后台应有进度 | 触摸前保存 AudioContext 时间线；松手恢复后台位置，覆盖正向、反向、循环及按住期间变速 |
| Slip Hot Cue 与抓碟嵌套 | 外层 Cue 松开时，抓碟仍可能保留旧预览时钟 | 恢复外层时间线时同步更新抓碟后台；暂停、定位、换曲、显式播放及关闭 Slip 清理旧抓碟时钟 |
| 音频处理器生命周期 | 新旧音源交接时，异步回调容易影响后续播放 | 每个实例拥有自己的源、包络、处理器及零输入尾声；淡出后释放旧实例；旧处理器报错不会暂停新实例；关闭引擎立即释放所有实例 |

代码位于 `src/audio.js`、`src/deck-performance.js`；`src/main.js` 为 Slip 抓碟显示后台虚线，`src/pad-ui.js` 同时显示 `SLIP SCRATCH` 后台位置。

## 验证方法

`tests/audio-core.spec.js` 新增 9 项测试。离线渲染使用 48kHz 合成 PCM，并直接读取混音 / EQ 前的音频，避免滤波器掩盖播放硬切；测试不依赖扬声器或人工听感。

- 立体声直流测试覆盖播放、跨正负电平跳点及同一时刻多次跳转后暂停；要求最大相邻采样差 < 0.01，最终完全静音，左右声道一致。
- 正向 / 反向 × 有循环 / 无循环，抓碟期间由 1.25 倍变为 0.8 倍；要求恢复位置与后台积分误差 < 0.1ms，并验证实际输出进入对应的 880Hz 音频区域。
- 440 / 660Hz 双声道、1.25 倍速度、Key Lock，在 0.7 秒与 1.4 秒改为 +12 / −12 半音；排除首次填充后，以 5ms RMS 窗口检测连续静音，要求最长 < 20ms，三个稳定区间的频率误差 < 12Hz。
- 实时浏览器测试覆盖 Cue 与抓碟嵌套、退出 / 替换运输、迟到释放，以及启用 Key Lock 后连续跳点 / 换向。要求旧实例最终清空、新实例继续有声，显式清理后无播放实例残留。

2026-10-22，新增专项 **9/9 通过**，完整 Playwright 回归 **171/171 通过**，耗时约 12.7 分钟，失败、跳过及 flaky 均为 0。新增测试等待演示音频载入且页面初始化结束后才操作播放器。

| 实测项 | 结果 | 测量范围 |
| --- | --- | --- |
| 播放 / 跳点 / 暂停的最大相邻采样变化 | 0.00260419；最终尾部与左右声道差异均为 0 | 48kHz、±0.25 电平的合成 PCM，DSP / EQ 前 |
| Slip 抓碟恢复 | 正反向 × 有无循环四种情形均与后台预期位置一致 | 抓碟期间 1.25 → 0.8 倍变速；同时验证恢复后的实际音频频率 |
| 连续 ±12 半音 | 两声道均未检出静音窗；左声道 440 → 880 → 220Hz，右声道约 653.3 → 1320 → 330Hz | 已运行 Key Lock 处理器、1.25 倍速度、5ms RMS 窗口；频率估计容差 12Hz，排除首次 DSP 填充 |

## 原版依据及限制

现有原版符号在 `evidence/audio-symbols-arm64.txt`：`setKeylock(bool)`（`0x10013a83c`）、`scratchTo(...)`（`0x1001345fc`）、`scratchStop(...)`（`0x100134ae4`）、`saveSlipPosition()`（`0x10009cc94`）、`restoreSlipPosition()`（`0x10009ccc8`）、`setPlayReverse(int)`（`0x1000950d4`）及 `TempoClock::incrementSamplePosition(int)`（`0x10028e7f8`）。这些只证明相关接口存在。

已有 REA 证据主要核实采样器组织与交互；先前对大体积原生主程序的音频目标反编译因 330000ms provider 超时未获得函数体。本轮依据现有证据与本地 PCM 复现优化实现，没有取得新的原版音频核心伪代码。4ms 淡化和生命周期策略为独立实现选择，并非已证明的原版参数。

仍需完成的音频工作：

1. 用相同真实音乐和测量信号，录取 DJUCED 与 MIXDESK 的输出，比较时延、瞬态、相位、频谱、失真与声道分离；现有测试只验证本地实现的正确性。
2. 优化首次启用 Key Lock、跳点和旁路切换时的 DSP 填充；连续移调消除了重建间隙，不代表所有操作零延迟。自然曲尾目前仍使用固定 250ms 尾声窗口，尚未自适应 DSP 延迟。
3. 抓碟仍是双向短音粒近似；逐次音粒交接、原生循环接缝、极端变速和复杂瞬态尚未完成专项优化。Jog 弯音的平滑速率与显示时钟积分仍待进一步核验。
4. 校准原版 EQ / Filter / FX 参数曲线、SYNC / Quantize 边界，补齐真实 Stems 分离与专业限幅。
5. 接入 Hercules 和实际音频输出，验证实体控件 / 灯光、耳机独立路由、多通道声卡及端到端延迟。当前没有真机验收。

## 手动试听

在本地页面播放一首熟悉的音乐。开启 KEY LOCK、调节速度，再连续切换几个移调值，检查是否出现整段短静音；随后回到 0 半音。开启 SLIP，拖动转盘后松开，观察后台虚线和恢复位置；再分别开启循环与 REV 重复操作。关闭 SLIP 后，抓碟松手应从抓碟位置续播。最后快速点击多个 Hot Cue，再暂停，检查是否有残留声音。主观试听仍需结合原版同音源录音比较。
