# DJ Master ASTRIBOT / STUDIO 项目介绍

## 项目定位

DJ Master 是一个面向 Astribot OS 的本地音乐预排 App，用于把两首音乐、DJ 操作、音效和机器人动作编排成一段可试听、可保存、可复用的演出草稿。

它覆盖“音乐预排”阶段：用户可以导入两首音乐，安排曲目片段和入场时间，把 DJ 设备操作拖到时间轴，再通过真实的 Web Audio 混音试听整段演出。当前版本不会连接实体 DJ 控制器、机器人或现场控台，也不会直接执行机器人动作。

项目使用 MixDesk 中已经逆向确认的 DJControl MIX 控件名称和动作意图作为编排依据。DJ Master 是独立的 Astribot OS App；MixDesk 可以继续作为后续现场操作和完整 DJ 工作台使用。

## 能解决什么问题

- 在演出前快速确定两首音乐的顺序、片段和转场位置。
- 把“什么时候推杆、什么时候按键、什么时候加音效”放到同一条时间轴上查看。
- 通过真实音频试听确认滤波、低频、音量、交叉淡变、变速、变调和采样器是否听得见。
- 为机器人动作预留合理间隔，避免多个动作在时间轴上堆叠或过于靠近。
- 保存本地草稿，在后续排练中继续修改、撤销、重做和重载。

## 主要功能

### 双 Deck 音乐预排

- 每个预排组包含两首音乐，分别对应 Deck A 和 Deck B。
- 支持 MP3、WAV、FLAC，单文件上限 150 MB。
- 支持导入、替换、裁剪起止位置、调整曲目顺序和设置 BPM。
- 导入后显示时长、BPM、首拍偏移和波形。
- 两首音乐可以从同一演出时间开始，也可以分别设置入场时间。
- 时间轴支持缩放、适配窗口、播放头拖动和音乐块拖动。

### 真实混音试听

试听使用 AudioContext 的音频时钟调度，不依赖页面动画时间。

- 两首音乐可以同时进入主输出。
- 转场使用等功率交叉淡变，避免交叉过程中音量明显塌陷。
- 可试听单首音乐，也可以试听完整预排混音。
- 播放头、事件状态和音频调度使用同一时间基准。
- 支持浏览器可解码的本地音频，不需要上传到云端。

### DJ 操作 / 音效菜单

DJ 操作和音效在界面上使用统一菜单和统一时间轴轨道。操作卡可以点击添加到播放头，也可以拖到指定时间位置。

每个操作会保存以下映射信息：

- 逆向映射文件。
- 实体控件名称。
- Deck 和控制通道。
- 原始动作名称。
- 映射值。
- 操作类型和音频试听状态。

菜单中的操作分为三类：

1. **连续控件**：保存起始值、目标值、单位、范围和曲线，例如音量推子、滤波和交叉推子。
2. **按键操作**：保存按下、保持和释放语义，例如 FX 按键和 Cue 类操作。
3. **一次性采样**：在时间轴上显示固定宽度标记，例如 Kick、Clap 和 Hat。

当前菜单包括：

- 播放 / 暂停、Cue、Hot Cue。
- 1/2/4/8 拍循环、前后 4 拍跳转、SYNC。
- 滤波渐入、低频收拢、FX 1–3、音量推子、交叉推子。
- 变速、变调、Kick、Clap、Hat。
- 搓碟倒放、Scratch 模式、停止播放。

### 已接入真实音频试听的操作

以下操作会在试听时实际改变浏览器音频图：

| 操作 | 音频表现 |
| --- | --- |
| 滤波渐入 | 低通 / 高通滤波频率自动化，可改变方向并平滑衔接 |
| 低频收拢 | 自动化控制低频 EQ，减少或恢复低频能量 |
| 音量推子 | 自动化控制对应 Deck 的通道电平 |
| 交叉推子 | 两个 Deck 之间执行等功率交叉淡变 |
| 搓碟倒放 | 倒放指定音源片段，再正放回原位置，并顺延后续事件 |
| FX 1–3 | 连接 Echo、Reverb、Flanger 等本地 DSP 效果，并按持续时长启停 |
| 变速 | 对时间轴中的音频片段自动化播放速率 |
| 变调 | 通过播放速率产生可听的音高变化 |
| Kick / Clap / Hat | 通过内置确定性采样器在指定时间触发一次采样 |

这些效果是基于 Web Audio 的本地 DSP 试听，目标是还原已确认的控件意图，不宣称复刻 DJUCED 或实体设备的专有 DSP 音色。

### 时间轴编排

- 音乐轨道、DJ 操作 / 音效轨道、机器人动作轨道和标记轨道分开显示。
- DJ 操作和音效共用一条可视轨道，保留 `dj` / `fx` 类型以兼容旧草稿。
- 固定按键显示一次性标记；持续效果显示可拉伸区间。
- 持续效果可以拖动右端调整持续时长。
- 同一轨道中时间重叠的事件会自动分层，避免视觉堆叠。
- 拖动操作时显示落点、持续时长和预期层级。
- 支持节拍吸附，可选择 1/4、1/2、1、2、4 拍；也可以关闭吸附自由摆放。
- 支持复制、粘贴、撤销、重做和删除事件。

### 搓碟倒放和演出时间

搓碟倒放采用“演出时间单向前进、音源位置可以回退”的规则：

1. 在当前音源位置截取一段片段。
2. 播放倒放片段。
3. 再正放回原位置。
4. 后续同一曲目的事件自动向后顺延新增时长。

时间轴同时保存演出时间和音源源时间，因此可以区分“演出进行到哪里”和“当前播放到音源的哪里”。

### BPM 和节拍辅助

- 有效嵌入 BPM 标签时优先使用标签。
- 没有标签时，可以根据音频瞬态估算 BPM 和首拍。
- BPM 和首拍来源会在界面中区分显示，便于人工复核。
- 裁剪曲目起点后，节拍网格仍以音源时间为依据保持对齐。

### 草稿和本地数据

- 草稿保存在 App 主机本地。
- 音频文件保存在 App 主机本地数据目录。
- 支持创建、读取、更新和版本化保存。
- 保存状态会显示当前版本和未保存修改。
- 页面关闭前不会自动把音频上传到云端。
- FastAPI 提供草稿、音频导入、音频读取和 SSE 状态流接口。

## 一分钟演示模式

点击“加载一分钟演示”可以载入两个内置的确定性演示音频：

- `Night Drive`
- `After Hours`

演示安排如下：

| 时间 | 内容 |
| --- | --- |
| 00:00 | 两首音乐同时起播 |
| 00:05–00:07 | 滤波变化 |
| 00:12–00:14 | 低频收拢 |
| 00:19–00:21 | 搓碟倒放与回放 |
| 00:26–00:34 | 两首音乐等功率交叉淡变 |
| 00:42–00:45 | 通道音量变化 |
| 00:45–00:58 | 保留收尾空间 |

演示音频用于验证时间轴、两 Deck 同时播放、真实混音、操作间隔和播放头同步。加载演示会产生未保存修改，需要点击“保存草稿”后才会写入本地草稿。

## 使用流程

1. 启动 App 并创建或打开本地草稿。
2. 导入两首音乐，检查时长、波形和 BPM。
3. 调整音乐片段起止位置、曲目顺序和转场重叠时长。
4. 从 DJ 操作 / 音效菜单点击或拖拽操作到时间轴。
5. 在事件属性中填写起始值、目标值、持续时长或按键保持时长。
6. 为机器人动作和标记预留间隔，只把它们作为预排数据保存。
7. 点击“试听混音”，检查两个 Deck 是否同时进入主输出，以及效果是否在正确时间发生。
8. 使用撤销 / 重做继续调整，确认后保存草稿。

## 当前边界

当前版本专注于音乐预排和本地试听：

- 不连接实体 DJ 控制器。
- 不调用机器人动作执行接口。
- 不接入现场控台、扬声器或 T1 Meta 接口。
- 播放 / 暂停、Cue、Hot Cue、循环、Beat Jump、SYNC、停止播放等传输类操作目前保存为映射事件，尚未全部接入独立的时间轴音频执行路径。
- 机器人动作显示为未验证的编排数据，需要在实际设备上测量准备、执行和返回时间。

## 开发和验证

在 `app_dj_master` 目录中执行：

```bash
python3 -m pytest -q
cd ui
npm run build
npx playwright test -c playwright.config.js
```

后端测试覆盖草稿保存重载、音频导入与读取、非法文件和路径拒绝、SSE 状态流。前端测试覆盖双曲目导入、时间轴拖放、事件编辑、倒放顺延、草稿保存重载、桌面布局和真实音频映射试听。
